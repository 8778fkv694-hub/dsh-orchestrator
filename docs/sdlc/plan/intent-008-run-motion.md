# INTENT-008 v1 · 运行状态动效

状态：accepted；日期：2026-10-30（Asia/Shanghai）。确认来源：本次 Codex 提问复述后，机主答复“确认，按此实现”。

原始输入：“刚才我手动点了运行和暂停，我需求是要看到运行中的动效，你转化一下我的意图并执行”。

复述：看板运行卡片、运行详情及当前步骤持续提供与真实状态一致的动态反馈；启动后的等待执行结果呈现蓝色流动指示与明确等待说明，暂停停止流动并显示暂停标志，等待人工决定显示琥珀色待决定提示，结束显示静态完成/取消状态。不虚构任务进度或执行端心跳。

## 设计与验收计划

1. 使用现有状态和 SSE 更新，无新运行依赖、无定时模拟进度、不改调度与权限。
2. 卡片增加可见动态指示；详情增加状态说明带与活动指示；当前步骤显示转动环，暂停显示静态暂停符号。
3. waiting-action 是工作单已派发、等待结果，文案明确“等待执行结果”，不据动画宣称外部任务已执行。
4. ready、paused、waiting-human、cancel-requested、done、cancelled 分别使用准确状态；只有 waiting-action 使用持续流动动画，人工等待使用静态标志。
5. 尊重系统 prefers-reduced-motion；即使关闭动画也保留状态文字、图标与步骤完成数量。
6. 客户端行为回归覆盖状态映射、暂停与终态无活动动画标记、当前节点与卡片/详情一致；全量回归；真实 Harness 看板点击启动/暂停/继续验证并留证。
7. 为机主展示可继续手动操作的隔离动效演示；合成数据明确标注，不触发真实新闻业务。

进度：已实现并完成自动回归与真实 Harness 启动/暂停/继续目视验证。机主最终体验反馈仍由机主给出。

验证结果：全量 55/55（客户端行为 5 项）；真实 Harness 两帧运行截图可见条形高度与步骤环位置变化；暂停后改为灰色静态标志；继续后恢复动态。operation 始终为同一值，无重复派发。记录见[动效证据](../../evidence/2026-10-30-run-motion/README.md)。
