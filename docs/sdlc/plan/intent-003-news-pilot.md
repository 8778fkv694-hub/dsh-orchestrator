# INTENT-003 v1 · 真实项目试跑（数字员工新闻管线移植）

状态：accepted；确认日期：2026-10-30；确认来源：机主在 DSH 会话中确认候选复述及三项范围选择（A/A/A：独立真实项目、按当前装机版新闻管线、1 次真实端到端运行）。

## 原始输入（机主原话）

> “目前我为了试跑这个功能，需要一个真实的项目。你把我的新闻管线移植到这里来，也就是把数字员工的新闻管线移植到这个项目中进行测试，看看它的功能实现。”

## AI 复述（确认对象）

为了让 dsh-orchestrator 用**真实业务管线**而不是玩具示例验证功能实现，在本机新建独立真实项目 `news-briefing`（起飞项目骨架；本地 git，不提交公开仓库），把数字员工当前装机版 `news` 轨道的**确定性采集层**移植进项目本地，并改编为 dsh-orchestrator 线性管线：

1. 人工四项偏好（领域/筛选/受众/消息全面性）由机主本人选择后写入定义；
2. 人工门（开始采集、接受交付）由机主本人点击；
3. 确定性任务：预检、采集（实时 RSS/HTML，24h 窗口，失败如实降级）、保存、HTML 渲染与哈希回执 `--verify`、聊天链接；
4. 模型任务：依据采集摘要写一份 Markdown 简报；
5. 最终由 dsh-orchestrator `deliveries` 对 Markdown/HTML/回执逐项核验；
6. 全过程保留 runId、门决策、产物哈希、模型步数与未验边界；不推送外部、不建定时、不改数字员工生产数据、不改 dsh-orchestrator 内核。

## 范围与边界

- 项目位置：`~/开发/news-briefing`（本地真实项目；新闻订阅配置与产物不进 git）。
- 数据：机主真实订阅（`sources.json`，85/272 启用），本轮实时抓取最近 24 小时、≤20 条、约 180 字/条。
- 基线：数字员工**当前装机版** `news` 轨道（含自建“消息全面性”门与聊天链接节点）。
- 真实模型按 DSH Desktop 当前线路计费；预算 1 次运行，模型步骤目标 ≤40、硬上限 60。
- 已知适配（详见 SPEC v3）：多选一人工门→`ask_user_question` + 二元门；变量/动态命名→稳定交付路径 + 历史副本；确定性节点→Agent 工作单调用脚本。
- 底座缺口（多选门、变量替换、动态命名）只登记，不擅自改内核。

## 验收判据

1. 项目与管线定义可独立审阅；`validate()` 通过，`references` 固定 AGENT/Intent/Spec/Plan 哈希。
2. 一次真实运行完成或**如实失败**：产出并通过 `deliver-report.py --verify`；人工门均由机主点击；证据含 runId、偏好、采集状态、产物 sha256、步数/耗时。
3. 不产生外部推送、不修改生产数据、不伪造新闻或哈希；未验边界如实列出。
