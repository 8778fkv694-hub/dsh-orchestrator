# INTENT-002 v1 · 本地管线看板与调度入口

状态：accepted；确认日期：2026-10-30；确认来源：机主在本任务会话中选择候选范围 **A（看板 + 实时状态 + 启动/继续调度，只发工作单，不执行外部动作）**。原始输入见下，未经确认的候选不作为正式 Intent。

- “只读页面加上启动按钮和实时状态显示可以吗”
- “我的补充需求你也要转化intent和spec”

## AI 复述（确认对象）

在**不改变“人的决定由 Harness 承担、外部执行由宿主工具承担”**边界的前提下，为 dsh-orchestrator 增加一个本地 Web 管线看板：

1. **只读展示**：运行列表、状态、节点进度、事件时间线、收据与产物哈希、当前待办（人工门/待提交/取消核对）。
2. **实时状态**：状态文件变化后 ≤1 秒内自动更新（SSE + 文件监听，断线自动重连，轮询兜底）。
3. **调度按钮**：对已由 Harness/CLI 确认创建的运行，提供“启动（发出下一步工作单）/继续/暂停/取消”，页面显示 operation ID；**不执行外部动作、不做人工门确认/对账、不创建运行**。
4. **安全与边界**：仅绑定本机回环地址（默认 `127.0.0.1`，`--host` 仅接受回环别名）；每进程访问令牌（可用 `--token` 显式指定，≥16 字符；进程存活期间有效并出现在启动输出的 URL 中）；Origin/自定义头校验；无 CORS；无外部命令与模型调用；页面明确标注“调度入口，不是 Harness 人工确认的替代”。
5. **不改变**：Intent 确认、人工门、对账、交付核验仍在 Harness 会话；核心、插件、CLI 现有行为与安全边界不变。

## 明确不做（本轮）

- 页面创建/确认 Intent、人工门确认、对账、完成提交（这些需要宿主人类确认通道）；
- 页面直接执行任务动作或运行脚本（那是候选 B，未获授权）；
- 远程/局域网访问、多用户账号与权限模型；
- 修改 Harness 客户端界面（内嵌页面留作后续）。

## 验收判据

- `orch view <workspace>` 本地启动，页面展示真实运行状态并实时更新；
- 按钮只产生调度动作（`next/pause/resume/cancel`），非法状态有可解释错误且不改状态；
- 只读开关可关闭动作端点；无令牌/错误 Origin/非本机 Host 被拒绝；
- 单元测试覆盖 API、渲染转义、安全、实时推送、只读与调度状态迁移；
- 有真实截图证据与证据边界说明；不引入凭据、外部命令或模型调用。
