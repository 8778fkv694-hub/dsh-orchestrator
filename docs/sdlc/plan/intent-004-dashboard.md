## AI 复述（确认对象）

把 dsh-orchestrator 的“人在环内”体验重构为两个相互配合、边界清楚的面：

### A. Harness 会话内的插件交互（结构化展开）

- 每次 `orch_*` 工具结果不再以“大段文字 + 原始 JSON”呈现；第一行只给当前状态/进度/下一步，结构化区块（目标、当前步骤、工作单、证据、失败原因、操作 ID）按需展开，原始 JSON 收进次要层。
- **需要人选择的地方**（意图确认、人工门、领域/筛选/受众等选项）一律通过 DeepSeek Harness 的提问卡（`ask_user_question` / `userQuestions`）呈现：选项清楚、可单选、由人点；模型不得代选；无回答/跳过不算确认。插件的人工门要支持**多选项**，不再被迫只有 confirm/reject。

### B. Dashboard 管理看板（人性化、先进、简单、好看）

- 首屏回答三个问题：**什么在跑、什么需要我、什么已完成**；不再把整页塞满文字。
- **结构化展开**：总览（L0）→ 运行/管线卡片（L1）→ 详情抽屉（L2：步骤流、证据/哈希、事件时间线、原始 JSON 仅高级里）。默认只显示摘要，点开才展开；卡片上的文字最多一两行。
- **管线库**：已登记管线（`pipelines/*.json`）以卡片展示，含名称、意图一句话、节点/交付项、最近更新；点开可看步骤流；不在此创建运行（创建仍在 Harness 里由人确认）。
- **实时操作**：对已创建的运行提供启动/继续/暂停/取消等调度操作（只发工作单/改调度状态，不执行外部动作），操作后立即反馈并实时更新；破坏性动作二次确认，错误用人话说明。
- **交互分工**：需要“人做决定”的（意图确认、人工门、参数选择）留在 Harness；Dashboard 负责观察、筛选、展开和调度，不做人工确认的替代，也不伪造确认记录。等待人决定的运行在看板上标成“待你决定”，并给出回到 Harness 的明确指引（runId/会话/下一步）。
- **视觉**：深色、精致、克制；状态色 + 图标 + 进度/步骤流 + 时间线；足够留白；响应式；可访问性（对比度、键盘、焦点）；不再是“文字墙”。

### 不做什么

- 不在 Dashboard 创建/确认 Intent、不做人工门/对账/交付确认（这些必须留在 Harness）。
- 不执行任务动作、不调模型、不推送外部、不做多用户/局域网权限。
- 不改宿主（DSH）本身；不破坏现有 `orch_*` 工具语义与 read-only/调度边界。

### 追加（2026-10-30，机主补充）

机主原话：“增加：运行记录管理也要，还有输出物，加进去。”

纳入本轮：

- **运行记录管理**：独立的“运行记录”视图（历史列表、状态筛选、搜索、详情、导出 JSON）；只读管理，不提供删除/归档（清理需另立授权与审计）。
- **输出物**：独立的“输出物”视图，只读列出工作区 `output/` 下的交付文件（路径、大小、更新时间、类型），可打开/复制路径；详情抽屉中的产物证据也可打开；只服务 `output/` 内普通文件并带沙箱 CSP。

## 成功判据

1. 首屏 3 秒内能看出运行状态分布与待办；默认视图无超过两行的段落；原始 JSON 默认折叠。
2. 领域/筛选/受众等选择题在 Harness 以选项卡呈现并由人点选；人工门支持多选项且记录所选值。
3. 看板可完成 启动/继续/暂停/取消 的实时操作并有即时反馈；待决定项有清晰回 Harness 指引。
4. 视觉经机主看截图验收；测试与证据齐全；不产生越界动作。
