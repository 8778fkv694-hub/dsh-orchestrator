## 原始输入（机主原话）

1. “另外，你可以把一些运行截图放到 README 里面在我这个开源项目的主页可以看到哦”
2. “我主要的目的是我这个开源项目的一些开源项目里面的一些设置，使它一开始就好用。为了这个目的，你转化一下吧，我这条意图你转化一下”
3. 前序补充：“这个新闻网页……我要每次要问你，你应该先自动的就打开实时更新，对不对？”
4. 前序补充：“我如何调用这个插件呢？……有没有什么 skill 或者有什么办法能够快速调用这个插件呢？”
5. 前序要求：评估管线实现、让看板人性化/先进/简单/好看、运行记录管理与输出物。

## AI 复述（确认对象）

**把 dsh-orchestrator 做成一个“一打开就好用”的开源项目**：第一次拿到它的人（包括机主自己）不需要读大量文档、不需要每次让 Agent 解释配置，就能在几分钟内看到真实可用的界面与示例运行，并且默认行为就是合理、安全、实时更新的。

具体包含六件事：

1. **一条命令起步**：从仓库直接运行一个零配置的 quickstart（自带示例工作区与演示数据），在本地打印（可选自动打开）一个已可用的看板 URL；不需要模型、不需要凭据、不碰用户主 profile。
2. **默认就好用的看板**：默认自动跟随最新运行/最新输出物；新闻/报告类输出物在页面内预览并随运行实时刷新；自动打开外部窗口默认关闭（可设置），避免突然弹窗；记住上次选择。
3. **Harness 内一句话调用**：随项目提供 DSH skill（触发词 + 标准配方），说“跑一条新闻简报/看一下运行/暂停它/对账”就能触发正确的 `orch_*` 流程，不用每次解释工具名。
4. **示例与演示素材**：提供脱敏的示例管线、合成演示运行/输出物与截图；真实个人新闻订阅、产物与凭据不进公开仓库。
5. **首页即说明**：README 放运行截图 + 三步 quickstart + 常见问题与边界；中英文对齐。
6. **出错也好懂**：启动/健康检查给出人话错误（Node 版本、工作区不可写、端口占用、插件未安装等），不把原始堆栈丢给首次使用者。

## 不做什么

- 不做托管服务、不发布 npm（包名已被占用）、不自动推送外部、不降低只读/令牌/人工确认边界。
- 不把个人新闻源、产物、凭据或运行数据放进公开仓库。
- 不改变 `orch_*` 工具语义，也不在未获授权时改宿主（DSH）。

## 成功判据（可观察）

1. 干净副本上 **≤3 条命令、≤5 分钟** 能得到一个显示示例管线与演示运行的本地看板 URL（不依赖模型/凭据）。
2. 新运行/输出物变化时看板自动跟随或给出明显提示；输出物可内嵌预览并自动刷新。
3. 仓库内包含可用 skill；用一句话触发配方能走通（在真实 Harness 会话中验证）。
4. README（中/英）在 GitHub 首页可见截图与 quickstart；链接全部有效。
5. 失败场景给出人话原因与下一步；既有测试与安全边界不回归。
6. 真实项目（新闻简报）能用同一套 quickstart/默认设置启动并跑通一次（人工门仍由人点）。
