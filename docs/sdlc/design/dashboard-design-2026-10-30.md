# 管线管理看板与插件交互设计（2026-10-30）

依据：候选 [INTENT-004](../plan/intent-004-dashboard.md)（待机主确认）。本文件是设计稿，不是已实现证明。

## 1. 目标与非目标

- 目标：human-friendly、先进、简单、好看。首屏看清“什么在跑 / 什么需要我 / 什么完成”；结构化展开；选择交回 Harness 提问卡；看板可实时暂停等操作。
- 非目标：Dashboard 不创建/确认 Intent，不做门/对账/交付确认；不执行任务、不调模型、不推送外部；不改宿主。

## 2. 两个面

**A. Harness 会话（决定在哪里发生）**
- 工具结果第一行：`状态 · 进度 · 下一步`；其下按需分块：目标 / 当前步骤 / 工作单（operation ID 可复制）/ 证据 / 错误与恢复建议。
- 选项类交互（领域、筛选、受众、门决策）用 DSH 提问卡：多选项、单选、由人点；模型不得代选；跳过/无回答不算确认。
- 人工门支持 `options`（向后兼容无 options 的 confirm/reject）。

**B. Dashboard（看 + 调度在哪里发生）**
- 只展示与调度；待决定项给“去 Harness 回答”的指引，不在页面里伪造选择。

## 3. 信息架构（首屏）

```
┌ Header: DSH Orchestrator · 管线看板    工作区 ▾   ● 实时   只读/调度   ⌕ 搜索   ⚙ ┐
├ 概览条: [进行中 2] [待你决定 1] [已完成 6] [已取消 1] [已登记管线 3]   ← 点击筛选 ┤
├ 左栏（可折叠）            中栏（默认）                        右栏（选中才出现）          │
│ 已登记管线                 运行卡片列表（按需分组）             详情抽屉                  │
│ · 管线卡（紧凑）            · 待你决定（置顶，醒目）             · 标题/状态/操作        │
│   名称                      · 进行中                             · 步骤流（节点图）      │
│   1 行意图                  · 就绪 / 暂停                        · 当前工作单 + 复制      │
│   节点/交付/更新            · 已完成/取消（默认折叠）            · 证据与哈希            │
│                                                               · 时间线（默认折叠）    │
│                                                               · 原始 JSON（高级折叠） │
└ 底栏: 最后刷新时间 · 连接状态 · 只读/调度说明 ────────────────────────────────────────┘
```

- 运行卡片（L1，最多两行文字）：状态图标+颜色、名称、进度环/条、当前步骤、更新时间；需要人时加“待你决定”角标。意图不默认展示（在详情里一行）。
- 默认不展开事件/JSON；用户点卡片才出现右侧抽屉。
- 待你决定置顶并显示“去 Harness 回答 / 复制 runId”的按钮与一句人话指引。

## 4. 结构化展开（三级）

| 层 | 内容 | 默认 |
|---|---|---|
| L0 总览 | 状态计数、待办队列、运行卡片 | 可见；无长段落 |
| L1 卡片 | 名称、状态、进度、当前步骤、时间 | 可见；≤2 行文字 |
| L2 抽屉 | 步骤流、工作单/操作 ID、证据表、时间线、原始 JSON | 点击后出现；JSON 默认折叠 |

规则：卡片意图截断一行；详情里的长指令/问题可展开；错误给“人话原因 + 建议动作”；任何地方不默认展示原始 JSON。

## 5. 步骤流与证据

- 步骤流：横向/纵向节点图，节点=task/gate/check，颜色：done 绿、current 蓝/琥珀、pending 灰、failed 红；gate 用菱形/门图标；点击节点显示 instruction/question/proofs。
- 证据表：路径、收据 sha256（前 12 位）、当前文件状态（一致/已变化/缺失/不安全）、字节数；`--verify` 结果单独状态条。
- 交付项：三件套以 checklist 呈现（Markdown / HTML / 回执），全部通过才显示“交付已核验”。

## 6. 操作（看板侧）

| 运行状态 | 看板可用按钮 | 说明 |
|---|---|---|
| ready | 启动（发工作单） | 需确认；显示 operation ID |
| paused | 继续 | 恢复调度 |
| waiting-action | 暂停、取消 | “等待执行结果”提示；执行仍在 Harness/CLI |
| waiting-human | 暂停、取消 | 显示“去 Harness 回答”，不做门确认 |
| cancel-requested | 无（只读） | 显示“请在 Harness 对账” |
| done/cancelled | 无 | 终态 |

- 取消二次确认；所有操作乐观反馈 + toast + SSE 刷新；失败给人话（含遗留锁处理指引）。
- 操作后 1 秒内 UI 更新；连接断开显示“轮询兜底”。

## 7. 视觉语言（提炼自 DSH 深色界面）

- 背景 `#0f1216`，面板 `#161a20`，卡片 `#1b2028`，描边 `#2a303a`；文字 `#e8eaed`，次级 `#9aa3ad`，弱 `#6b7480`。
- 状态色：进行中蓝 `#6ea8fe`，等待/待决定琥珀 `#e0a742`，完成绿 `#41c486`，取消红 `#e06c75`，暂停灰。
- 字体：系统 UI 12–20px；等宽只用于 id/hash/路径；卡片圆角 12px；间距 8/12/16/24；图标 16px；轻阴影/无重边框。
- 动效 120–160ms；`prefers-reduced-motion` 关闭动效；对比度满足 WCAG AA；焦点环可见；键盘 Esc 关抽屉、`/` 聚焦搜索、Tab 顺序合理。
- 响应式：<900px 单列，抽屉全屏；触控目标 ≥40px。

## 8. 插件侧（Harness 会话）

- `orch_gate`：若 gate 定义带 `options`，用 DSH 提问卡呈现多选项（单选）；无 `options` 时保持 confirm/reject。
- `orch_create`/`orch_next`/`orch_complete` 等结果：首行摘要 + Markdown 结构化区块；工作单给出 operation ID；错误给“原因 + 下一步 + 是否需要人”。
- 会话内不展示大段 JSON；详细证据可引用 Dashboard 的 run 链接/路径。

## 9. 数据与接口

- Dashboard 继续用现有只读 API：`/api/runs`（含 runs、pipelines、warnings）+ `/api/runs/:id`；调度 `POST /api/runs/:id/(next|pause|resume|cancel)`；无需新增服务端接口即可支撑新 IA。
- 插件侧改动：`core.validate` 允许 gate `options`；`plugin.orch_gate` 使用选项提问并记录所选 label；兼容旧定义。

## 11. 规模化补充（INTENT-006 候选）

- **分类**：管线按目录/可选 index 元数据分类（新闻/自动化/开发…），运行按状态 + 时间桶 + 管线分组，输出物按类型/日期分组；组头显示数量并可折叠。
- **排序**：默认“最新”；可切换“最常用”（运行次数、最近使用）、“名称”、“状态”；每个视图记住。
- **置顶/收藏**：管线和运行可本机置顶；置顶区固定在前；最常用只由运行历史推导，不伪造。
- **规模**：搜索 + 分类 + 筛选组合；加载更多/分页；单页渲染上限；200 运行/50 管线/200 输出物下首屏仍可读。
- **默认秩序**：待你决定/失败 → 进行中（最新在前）→ 近期完成；零配置可用。
- **持久化**：视图、筛选、排序、折叠状态本机保存；不服务端共享。
