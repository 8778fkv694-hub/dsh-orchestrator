# SPEC-001 v1 · 首版工程契约

依据：INTENT-001 v1 accepted。状态：实施设计基线；2026-10-30。实现验收与边界见[验证记录](../test/verification.md)与[STATUS](../../../STATUS.md)；本文不声称覆盖范围外能力。

## 人能读懂的要求

人确认要做什么后，AI可创建可复用管线。用户能看懂正在做哪一步、要决定什么、什么结果才算完成；中断后接续不重复未知副作用；交付由明确产物判据核验。首版采用工具回执显示状态，独立界面后续再做。

| ID | 行为与边界 | 验收证据 |
|---|---|---|
| S1 | 定义与运行分离，严格校验节点/版本，运行固定快照 | 定义变更不影响已运行实例；非法定义拒绝 |
| S2 | 通过宿主的人类提问服务确认AI复述；记录精确内容、回复和版本，拒绝/超时不接受 | 插件测试及真实Harness人工场景 |
| S3 | 首版线性节点支持task（agent/script）、gate、check；任务经宿主现有工具执行 | 纯脚本及混合样例真实闭环 |
| S4 | 持久化运行、当前步骤、操作ID、事件和证据；写成功后才发出动作 | 重启/存储失败/并发反例 |
| S5 | 任务发出后标效果未知；不能仅凭模型输出推进。完成须核对预先声明的文件证据 | 未产生/不匹配/旧产物拒绝 |
| S6 | 暂停、取消与外部任务停止分开；未知动作恢复先核验，重试须真人决定并留记录 | 中断零盲重发、否决和取消场景 |
| S7 | 最终交付独立核验所有交付项；状态区分done、failed、waiting等 | 缺项不能done |
| S8 | 起飞衔接引用AGENT、Intent、Spec、Plan路径与版本，根目录受限 | 路径越界/符号链接拒绝，关联内容摘要固定 |
| S9 | 插件作为dsh.bundle打包，可加载/卸载；不自建不受宿主管理的shell/模型通道 | 真实宿主工具注册/调用/清理与隔离安装证据 |
| S10 | 开源仓库含中英文入口、示例、安装恢复、验证边界；真实Harness端到端通过后才称交付完成 | 仓库回读与端到端收据 |

## 实施选择

核心为Node ES模块，无Electron依赖。任务发出与执行结果提交分开：插件给Harness Agent具体工作单，Agent使用已有工具执行；独立CLI可由明确允许的执行适配器驱动脚本，不在模型工具中直接暴露任意shell。纯脚本能力还须验证无需模型的驱动路径。

管线任务含instruction与文件证据（路径、最小长度、内容锚点/哈希），任务前冻结基线，要求本次产生或修改。文件证据仅证明声明的文件性质，不代称真实业务系统写入。对外业务适配留待专用oracle。

本地持久层单机文件原子替换与互斥；明确故障/并发边界，不宣称分布式事务或恰好一次。敏感配置不复制到开源仓库。线性节点为首版范围，不冒称DAG/跨端兼容已完成。
